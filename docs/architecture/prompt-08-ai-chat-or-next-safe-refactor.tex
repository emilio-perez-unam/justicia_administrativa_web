\section*{AI Chat Ownership Audit}
\texttt{chat\_area.dart} was selected because it was dirty only with coherent,
AI-chat-specific, site-local changes. No existing
\texttt{ai\_assistant/chat/**} files were present, so the extraction could
proceed without absorbing unrelated site-local work.

\section*{Component Boundaries}
\begin{itemize}
  \item \texttt{chat\_area.dart} remains the hook-based public boundary. It
  owns message state, conversation loading, source restoration, file upload,
  voice input, send orchestration, drag-and-drop conversion, and scroll
  behavior.
  \item \texttt{chat\_message\_list.dart} owns transcript rendering, loading
  state, empty-state dispatch, and the typing indicator.
  \item \texttt{chat\_empty\_state.dart} owns the branded welcome state.
  \item \texttt{chat\_composer.dart} owns attachment chip rendering, text
  input, upload progress, voice, web-search, and send controls.
  \item \texttt{chat\_drop\_overlay.dart} owns the drag-and-drop visual
  affordance.
\end{itemize}

\section*{UI and Accessibility}
The refactor preserved the conversation hierarchy, user/assistant bubble
renderer, loading state, typing copy, attachment chip, upload progress,
voice/search/send controls, drag overlay, and brand treatment. No new visual
controls or decorative elements were introduced.

\section*{Architecture Notes}
This slice uses composition and presentational component extraction rather than
new domain abstractions. \texttt{Message} remains the existing UI data
contract, and \texttt{ChatService} plus \texttt{VoiceService} stay behind the
stateful hook boundary. No new ADTs, repositories, services, or global view
models were introduced. Actor-model abstractions were not needed: asynchronous
work is explicit in the chat boundary callbacks and does not require a local
message actor system.
